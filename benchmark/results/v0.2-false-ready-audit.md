## Scoring fixes

- `False ready` now counts only `NOT_READY -> READY` and uses NOT_READY trials as its denominator.
- `Missed warning` separately counts `WARNING -> READY` and uses WARNING trials as its denominator.
- Dependency matching ignores `ecosystem` on non-package requirements; ecosystem remains part of the identity of package requirements.
- Controlled aggregation no longer copies an invalid ecosystem onto non-package predictions.
- Ground Truth, predictions, prompts, Java inspection results, and readiness labels were not changed.

## V0.1.1 versus V0.2

The numerical `1.2% -> 4.4%` change is **not directly comparable and is not a strict false-ready regression**:

- Both old values measured NOT_READY and WARNING together; strict false ready is 0.0% in both versions.
- Under the corrected definition, the hybrid missed-warning rate is 1.9% in V0.1.1 and 7.8% in V0.2.
- V0.2 adds 147 in-scope package labels and four package blockers.
- Three Skills changed readiness after package blockers entered scope: two READY -> NOT_READY and one WARNING -> NOT_READY.
- The model, pinned Skills, three-run protocol, and base environment stayed fixed, but the dataset version, dependency scope, extraction prompts, label distribution, and scoring definitions are not identical.
- Every V0.2 package-blocker trial was classified non-READY; package false ready is 0.0%.

## Final conclusions

1. **Is 4.4% a genuine V0.2 regression?** `NOT DIRECTLY COMPARABLE`. It was a missed-warning metric under an incorrect label, while the evaluated scope also changed.
2. **Is there a Java, handoff, parser, verification, aggregation, or scoring bug?** No Java/handoff/parser/verification/readiness-aggregation bug was found in the audited cases. One benchmark-scoring/normalization bug was found and fixed.
3. **Does this block v0.2.0?** `NON_BLOCKING`. The saved results contain no strict false ready, all package blockers were caught, and the scoring correction requires no model rerun.
